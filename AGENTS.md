# Repository Guidelines

## Project Structure & Module Organization
- `mc1/`: Python package and public API entry points (`__init__.py`, `__main__.py`), plus graph/model helpers.
- `c++/`: C++23 extension sources built with `pybind11` and linked against `gccjit` (`compiler.cpp`, `dag.cpp`, `audio.cpp`, `python.cpp`).
- `test/`: Python `pytest` suite (`*_test.py`) and golden outputs (`compile_synth.expected.txt`).
- `poc/`: experimental prototypes; keep production-facing changes in `mc1/`, `c++/`, and `test/`.
- `.build/`: local build artifacts generated by scikit-build/CMake.

## Build, Test, and Development Commands
- `uv sync --dev`: create/update the dev environment from `pyproject.toml` and `uv.lock`.
- `uv run pytest -q`: run the full Python test suite.
- `uv run pytest -q test/dsp_test.py`: run a focused test module during iteration.
- `uv run python -m mc1`: start the interactive MiniCollider REPL.
- `uv run python -m build` (optional): build wheel/sdist via scikit-build-core.

## Coding Style & Naming Conventions
- Python: 4-space indentation, PEP 8 naming (`snake_case` for functions/modules, `CapWords` for classes), and explicit assertions in tests.
- C++: target C++23 (see `CMakeLists.txt`), keep headers minimal and APIs clear across `*.hpp`/`*.cpp` pairs.
- Keep modules focused; prefer small, composable graph/DSP primitives over large multi-purpose functions.

## Testing Guidelines
- Framework: `pytest`.
- Test files must end with `_test.py`; test functions use `test_*` names.
- Add regression tests for bug fixes and behavior changes.
- For output-stability checks, update golden files intentionally and review diffs (for example `test/compile_synth.expected.txt`).

## Commit & Pull Request Guidelines
- Existing history favors short, imperative commit subjects (for example: `osc`, `wrap_tau`, `scikit-build-core`).
- Prefer clear subjects describing the behavioral change; use optional prefixes (`feat:`, `fix:`) when useful.
- PRs should include: purpose, key design choices, and exact verification commands run (for example `uv run pytest -q`).
- Link related issues and include console snippets or diffs when touching compiler/golden-output behavior.
